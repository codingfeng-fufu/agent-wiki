# LLM Wiki 理念

LLM Wiki 的核心想法是：让 agent 维护知识，而不是每次回答问题时重新从原始文件里检索。

这个项目是对 Andrej Karpathy 的 LLM Wiki 想法的实现：让 LLM agent 维护一个 Markdown wiki，而原始资料保持不可变。这个仓库是该模式的一个独立本地实现，不是 OpenAI、Anthropic、Model Context Protocol、qmd、Obsidian 或其他被引用工具的官方项目。

常见 RAG 工作流会在提问时搜索原始资料片段，然后生成回答。这个方式有效，但回答过程中形成的结构很容易留在聊天历史里，不会变成下一次可以复用的知识。

LLM Wiki 在原始资料和 agent 之间放一个持久的 Markdown 维基层：

```text
raw/ 不可变证据 -> wiki/ 持续维护的页面 -> MCP 工具给 agent 调用
```

`raw/` 是证据层，agent 读取但不改写。`wiki/` 是维护层，agent 可以创建来源页、概念页、实体页、比较页和分析页，并使用 Obsidian 风格的 `[[links]]` 把它们连接起来。

这样做的价值在于积累。新资料不只是被索引，还会更新旧页面、补充链接、指出矛盾、修正过时结论。一次高质量查询也可以保存为新的分析页，成为后续问题的上下文。

人的角色是选择资料、提出问题、判断方向和价值。agent 的角色是做繁琐但重要的维护工作：总结、链接、归档、记录引用、保持一致性。

这个模式适合长期研究、个人知识库、读书笔记、课程笔记、团队记忆、竞争分析、尽职调查，以及任何需要知识随着时间增长的场景。
