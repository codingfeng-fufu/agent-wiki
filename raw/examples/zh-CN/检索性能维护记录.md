# 检索性能维护记录

日期：2026-05-04
来源类型：合成性能维护记录

## 问题描述

agent 如果每次搜索都要重新加载索引、启动重型模型或等待外部进程，就会倾向于少搜索，直接凭上下文猜测。  

这会降低回答可靠性，也会让 agent 更容易遗漏已有 wiki 里的信息。

## 目标行为

- 默认搜索路径要足够快，适合高频 agent 调用。
- 深度搜索只在高召回场景使用。
- 长时间会话可以预热搜索 daemon，避免重复冷启动。
- 搜索结果应该告诉 agent：当前 query 是否需要 deep search。
- 搜索改动后必须跑 benchmark，避免质量回退。

## 推荐指标

- 常见 query 的响应时间。
- `Recall@5`
- `HitRate@5`
- `MRR@5`
- 最差 query 列表。
- deep search 是否复用 daemon。

## 维护建议

如果 fast search 的召回足够好，就不要默认启用 deep search。  
如果用户连续执行多个高召回查询，可以启动 daemon：

```bash
.venv/bin/llmw search-daemon start --deep
```

然后让 MCP 或 CLI 复用这个后端，避免每次都重新初始化。
