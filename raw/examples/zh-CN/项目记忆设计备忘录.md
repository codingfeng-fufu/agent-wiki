# 项目记忆设计备忘录

日期：2026-05-04
来源类型：合成设计备忘录

## 背景

一个 coding agent 在长期项目里经常需要重复读取同一批上下文：项目目标、历史决策、发布流程、安全约束、性能瓶颈、测试策略，以及哪些文件不能随意改。  

如果这些信息只留在聊天记录里，每次新会话都会重新发现一遍。这样不仅慢，也容易丢掉之前已经形成的判断。

## 设计目标

把 Markdown wiki 作为 agent 的长期记忆层：

- `raw/` 保存不可变的原始证据。
- `wiki/` 保存 agent 维护后的结构化知识。
- 重要结论必须能追溯到来源。
- 常见问题的回答可以保存成新的 wiki 页面。
- 写入操作需要先计划、预览，再执行。

## 典型页面

- 来源页：记录一份原始资料的摘要、范围和 source_id。
- 概念页：解释一个可复用概念，例如“安全写入”或“检索守护”。
- 分析页：把多个来源综合成一个判断，例如“发布前检查策略”。
- 索引页：帮助 agent 和人类快速找到相关页面。
- 日志页：记录摄取、维护、查询保存等事件。

## 判断标准

这个记忆层是否有效，可以看几个信号：

- agent 是否减少了重复搜索原始资料的次数。
- 新 source 是否会更新已有概念页。
- 旧结论被新资料挑战时是否能被标记出来。
- 重要回答是否能从聊天记录沉淀到 wiki。
- health check 是否能发现断链、缺元数据、索引过期等问题。
